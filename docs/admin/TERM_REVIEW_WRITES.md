# 용어 검수 저장 켜기 (M5 보호 + M6 저장 연결)

2026-10-29 · 사용자 요청 「용어를 실제로 검토할 수 있도록」

## 확인한 사실

- M4 저장 기반(`20261028125014_admin_term_storage.sql`)은 문서에 「운영 미적용」으로 적혀 있었지만, main 푸시 때 Supabase 연동으로 **이미 운영 DB에 적용돼 있었다**(anon 호출이 404가 아니라 `permission denied` 42501). 쓰기 준비값은 기본값(false)이라 저장은 계속 잠겨 있었다.
- 같은 이유로 이번 마이그레이션도 main에 푸시하면 1~2분 뒤 적용된다.

## 바꾼 것

### DB — `20261029150000_term_review_writes.sql`

- **배치 보호(M5)를 DB 트리거로**: 워커가 어떤 경로로 쓰든(전체 glossary 교체, sense 연결, span·정식 명칭 채움, 후보 갱신·삭제·승격, 사전 재수입) 같은 규칙이 걸린다. 워커 코드는 바꾸지 않았다.
  - 검수한 의미: 표기·정의·종류·범위·메모·검토 상태를 배치가 바꾸지 못하고, 지우지 못한다. 별칭도 고치기·지우기·새로 붙이기를 막는다.
  - 검수한 후보: 표기·정의·정식 명칭·검토 상태를 지키고, 「안 보이는 후보 정리」 삭제를 막는다. 사전 승격(sense_id 연결)·출현 수 갱신은 받는다.
  - 검수한 적용 위치(`rootgist_admin.occurrence_review`): ko_span·sense_id·sentence_ids·highlight·정의를 배치가 바꾸지 못한다. 논문을 다시 만들며 행을 지우는 것은 막지 않고(자동 처리를 멈추지 않는다), 검수 표시만 지워 다시 「검토 필요」가 된다.
  - 보호를 건너뛰는 경우: 관리자 command 트랜잭션 안(`rootgist.admin_write`), 서비스 키가 아닌 역할(마이그레이션·SQL 편집기의 수동 수정).
- `apply_patch`를 같은 본문 + 보호 해제 + 검수 표시로 교체.
- `admin_claim_term_writer(actor)`: 관리자 UUID를 저장소에 적지 않고, 서버가 처음 저장할 때 서버 환경값(ADMIN_USER_ID)으로 한 번만 등록한다. 이미 다른 값이 있으면 바꾸지 않는다.
- `admin_term_review_marks()`: 목록 상태용 검수 기록(원문·번역 없음).
- 준비값: `worker_contract_version=1`, `writes_enabled=true`.

### 관리자 웹

- 저장 경로: `POST /api/admin/v1/term-commands` 하나만 연다(다른 쓰기는 423). 관리자 확인 → 같은 출처·JSON만(CSRF) → DB command. 원본 상태는 `GET /api/admin/v1/term-target/{sense|candidate|paper}/{key}`.
- 서버 전용 RPC 연결(`lib/supabase/term-rpc.ts`)은 이름을 정한 6개 RPC만 부른다. 조회는 기존 읽기 전용 전송기를 그대로 쓴다.
- 가상 데이터 모드는 같은 규칙을 메모리에서 흉내 내 로컬에서 저장 흐름을 시험할 수 있다(production에서는 fixture가 켜지지 않는다).
- 미리보기 규칙을 앱(ed02106)과 맞췄다: 사전 연결·승인과 상관없이 번역문 표기, 그다음 보이는 대응어, 그다음 번역문에 남은 영문. 낱말 경계(RAG ≠ RAGAS, 한글은 앞 글자). 「n회 일치」도 같은 규칙으로 센다.

## 검수 흐름(UI/UX Pro Max: 키보드 탐색·로딩 피드백·확인 대화·인라인 오류 지침 적용)

- 기본 목록은 「검토 필요」만. 끝낸 항목은 목록에서 빠진다. 칸이 비면 「모두 검수했어요」.
- 적용 위치: 번역문에 있는 후보 표기를 칩으로 보여 주고, 번역문을 드래그하면 「선택한 「…」」 칩이 생긴다. 「확인하고 다음」.
- 사전 의미·후보: 한국어 표기·일반 정의·메모를 바로 고친다. 「승인하고 다음」, 「수정 필요」(메모 필수), 「반려」(두 번 눌러야), 고치기만 할 때 「저장만」. 후보의 빈 표기는 AI 제안으로 채워 둔다.
- `⌘/Ctrl+Enter` 확인·승인하고 다음(입력 중에도), J/K 이동, `/` 검색. 저장 뒤 다음 항목으로 넘어가고 본문에 초점을 둔다.
- 하단 상태 줄(aria-live): 저장 중 → 「…했어요 · 시각」(후보는 「사전에는 다음 배치(02:17)」), 오류는 같은 자리에 이유와 「다시 시도」. 다시 시도는 같은 작업 ID라 두 번 저장되지 않는다. 충돌(409)이면 최신 원본을 다시 불러오고 입력은 남긴다.
- 저장 뒤 목록은 이전 내용을 보인 채 새로 고친다(깜빡임 없음).
