# ROOTGIST 용어 검수 집중 화면 — 디자인 검토안

2026-10-29 · UI/UX Pro Max 적용 · 승인 전 시안

## 목적과 현재 상태

사용자 요청은 “한 화면에서 용어를 편하게 검토하고, 논문 등 다른 메뉴는 없애기”다. 기존 앱의 Ink & Paper 색과 글꼴을 유지하면서 관리자 웹을 용어 검수 전용 도구로 단순화한다.

분석 기준은 관리자 배포 632a18b 및 기존 운영 문서다. 동시에 진행 중인 다른 소스/DB 설계 변경은 이번 시안에 적용하지 않았으며 실제 반영 직전에 최신 상태를 재대조한다. 현재 관리자 배포는 조회/로컬 미리보기만 가능하다. M4 저장 기반은 로컬 검증 상태이고 M5 워커 수정본 보호·M6 저장 UI가 남아 있다. 이 시안이 저장 권한이나 운영 DB 적용을 승인하거나 활성화하지 않는다.

**이번 결과물은 분리된 정적 HTML/CSS/JS 시안이다. 실제 관리자 소스·메뉴·배포·Flutter·워커·DB는 변경하지 않았다.** 모든 예문/논문 ID/완료 상태는 가상이며, 임시 저장·승인은 브라우저 메모리에서만 시연한다. 새로고침하면 초기화된다.

## 현재 불편의 원인

- 사이드 메뉴, topbar, 환경 배너, 작은 창 안내, 큰 제목/설명이 세로 공간을 차지한다.
- 중앙에 사전 의미→정의→별칭→연결 논문→영문→번역→강조 입력을 세로로 쌓아 중요한 적용 위치가 아래로 밀린다.
- 오른쪽 미리보기가 본문과 분리되어 길게 반복된다. 폰 장식보다 실제 강조 문장을 확인하는 일이 중요하다.
- 좁은 창에서 3열을 계속 유지하거나 단순히 글자를 줄이면 문맥 비교가 어려워진다.

## 제안 구조

첫 진입을 `/admin/terms`로 모으고 관리자 전체를 “ROOTGIST · 용어 검수” 하나의 작업 공간으로 만든다. 대시보드·논문·뉴스·공지·출처/운영 메뉴를 신규 UI에서 제거한다. 숨긴 메뉴를 다시 모은 ‘기타’ 메뉴도 만들지 않는다. 논문은 용어가 등장한 문맥/연결 논문 선택으로만 남긴다. 기존 데이터나 API 삭제는 이 디자인 범위가 아니다. 실제 반영 시 오래된 다른 화면 URL은 인증 경계를 유지한 채 용어 화면으로 안내/리디렉트한다. 상단 계정 영역의 로그아웃은 유지한다.

| 영역 | 역할 | 기본 노출 |
| --- | --- | --- |
| 상단 52px | ROOTGIST/용어 검수, 시안 표시, 도움말 | 항상 |
| 왼쪽 224px | 검색, 적용 위치/사전 의미/후보, 상태, 검토 목록 | 넓은 창 |
| 가운데 가변 폭 | 용어, 연결 논문, Axx 문장, EN/KO 비교, 강조 표기, 앱 표시 예상 | 항상 |
| 오른쪽 300px | 한국어 표기, 일반 정의, 별칭, 이 논문에서의 뜻, 중복 후보, 메모 | 넓은 창 |
| 하단 60px | 상태, 수정 필요, 임시 저장, 확인 후 다음 | 항상 |

페이지 전체를 스크롤하는 대신 목록과 긴 문장/정의만 영역 안에서 스크롤한다. 필수 도구와 주요 동작은 화면 밖으로 사라지지 않는다. 긴 문장 전체가 항상 스크롤 없이 보인다는 약속은 아니다.

핵심 작업 순서는 **번역 문맥 확인 → 표기/의미 확인 → 강조 결과 확인 → 다음 항목**이다. 사전 의미를 먼저 다 읽어야만 문맥을 볼 수 있는 기존 순서를 바꾼다.

## 검토한 대안

| 대안 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| 적응형 3열: 목록 / 문맥 / 사전 | 넓은 창에서 비교와 편집 동시 노출, 반복 검수에 유리 | 좁은 창에서는 패널 전환 필요 | 추천·시안 제작 |
| 2열: 목록 / 사전·문맥 세로 | 화면 구조가 단순 | 정의가 길면 적용 위치가 다시 아래로 밀림 | 핵심 불편이 남음 |
| 중앙 문맥 + 사전 전용 팝업 | 문맥 폭을 가장 크게 사용 | 넓은 화면에서도 매번 사전을 열어야 함 | 좁은 창에만 적용 |

추천은 설계자 제안이며 아직 사용자의 디자인 승인으로 간주하지 않는다.

## 화면 크기와 확대

- **1200px 이상:** 224px / minmax(0,1fr) / 300px. 1280×720에서 본문 비교, 강조 입력, 미리보기, 사전 필드, 주요 버튼을 함께 확인했다. 페이지 가로/세로 overflow 없음. 가상 데이터 기준 오른쪽 필드도 내부 추가 스크롤 없이 배치했다.
- **960–1199px:** 목록은 ‘검토 목록’ 버튼으로 펼치고, 문맥+사전 2열 유지.
- **600–959px:** 문맥에 집중. 목록과 사전은 각각 상단 버튼으로 여는 패널. 752×720 시안과 사전 패널 열기/닫기를 확인했다. 창이 좁을 때 세 영역을 동시에 축소하지 않는다.
- **599px 이하:** EN/KO를 위아래 비교. 작은 보조 정보는 줄이고 핵심 동작은 유지한다.
- **높이 630px 이하/높은 확대:** 전체 페이지 스크롤을 허용해 텍스트나 입력을 잘라내지 않는다. ‘한 화면’ 때문에 확대를 막지 않는다.
- 좁은 창의 패널은 modal, 배경 inert, Tab 순환, Escape 닫기, 호출 버튼으로 초점 복귀를 적용한다. 패널이 열려 있는 동안 J/K·확인 후 다음 전역 단축키는 차단한다.

정적 시안의 렌더러는 AI 검토 표시 OFF라는 고정 가정 아래 예문 한 문장의 첫 부분 문자열 일치와 승인 여부만 시연한다. 전체 앱 매칭 엔진의 대체품이나 실제 앱 표시 회귀 검증이 아니다. 실제 반영 시에는 기존 `admin/src/lib/domain/display.ts`의 검증된 projection을 그대로 사용해야 한다.

## 중요한 검수 규칙

- **사전 의미 승인과 논문별 적용 확인은 별개다.** occurrence의 주요 동작은 ‘적용 확인 후 다음’, sense는 ‘의미 승인 후 다음’, candidate는 ‘후보 검토 후 다음’으로 바꾼다.
- 같은 표기가 2회 나와도 현재 앱이 첫 1회만 강조하면 ‘2회 일치 / 앱은 첫 번째 1회 강조’로 함께 보여 준다. 두 번째 등장만 지정할 수 있는 것처럼 선택 UI를 만들지 않는다.
- 원문과 번역의 강조 위치를 즉시 비교한다. `ko_span` 일치가 0이면 설명을 입력 옆에 표시하고 적용 확인 동작을 막는다.
- 시안은 AI 검토 용어 표시 OFF를 가정한다. 실제로는 의미 approved 또는 표시 설정 ON + pending + AI first_pass_complete이면 표시될 수 있다. source_machine_translation_verbatim 정의는 승인 가정에서도 제외된다. 전체 조건은 기존 projection을 따른다. 가정이 실제 승인 상태를 바꾸지 않는다.
- Axx 탭은 문맥 탐색만 수행하며 초안 입력을 유지하고 일치 여부를 다시 확인한다. paper_glossary.sentence_ids를 바꾸지 않는다. 실제 적용 문장 변경 UI는 M6에서 별도 계약으로 구분한다. 다른 항목/유형으로 이동할 때 변경이 있으면 계속 검토/버리고 이동/임시 저장 후 이동을 제공한다.
- 확인 후 다음/수정 필요 예시에서 입력은 메모리 초안으로 보관한다. occurrence의 사전 필드 변경은 적용 위치 확인과 함께 승인하지 않고 초안으로만 남긴다. 후보 검토 결과는 사전 동기화 대기이며 즉시 사전 반영 완료가 아니다.
- 저장/승인에 필요한 실제 DTO·충돌·버전·감사·멱등성은 기존 M4~M6 계약을 따른다. 시안의 완료 체크 표시는 그 계약의 구현 완료가 아니다.

## 동작과 접근성

시안에서 검색, 빈 결과, 상태 필터, 검수 유형, 항목 전환, A04~A06 비교, 강조 입력/일치 수, 현재/승인 가정, 별칭 추가/삭제, 유사 용어 비교, 변경 경고, 로컬 임시 저장, 다음 항목을 체험할 수 있다.

- `/`: 검색. J/K: 다음/이전. 입력 중 일반 항목 이동 단축키는 무시한다.
- ⌘/Ctrl+Enter: 확인 후 다음 예시. Escape: 패널/대화상자 닫기.
- 식별 가능한 라벨과 focus-visible. 상태는 색과 텍스트를 함께 사용한다.
- 버튼은 데스크톱에서 32–38px 기본, coarse pointer에서 주요 컨트롤 44px 이상. 의미 없는 진입 애니메이션은 없고 reduced-motion을 반영한다.
- 긴 용어/본문은 줄바꿈하며 가로 스크롤을 만들지 않는다. 긴 글은 영역 스크롤로 읽는다.
- 실제 반영에서는 로딩 시 패널 크기 유지, 선택 항목별 오류/재시도, 명시적인 상태 표시, 0건/문맥 없음/의미 미연결 상태가 필요하다.

## 브랜드와 스킬 적용 기록

Ink & Paper 토큰: bg #F4F4F1, paper #FAFAF7, white surface, ink #0E0E0D, 본문 #33332F, muted #62625D, line #DCDCD5, 강조 #FFEFA3. 본문은 Pretendard, 영어는 Source Serif 4. 폰트 파일은 기존 프로젝트에서 읽어 시안에 복사했고 기존 파일은 변경하지 않았다.

UI/UX Pro Max `--design-system`을 실제 실행했다. 첫 editorial 질의의 Hero+CTA, 재질의 admin dashboard의 Glassmorphism/다크·초록 추천은 작업과 브랜드에 맞지 않아 채택하지 않았다. `keyboard focus visible`의 Focus States/Focus Not Obscured와 `responsive layout`의 Horizontal Scroll/Viewport Meta 지침은 적합해 적용했다. split view/progressive disclosure/stack overflow 질의 결과는 정확한 설계 근거가 아니어서 배치 결정에 사용하지 않았다. 3열의 치수/동작은 실제 코드·사용자의 검수 우선순위·브라우저 시각 검증을 바탕으로 한 제안이다. 무관한 검색 결과를 정답으로 포장하거나 스킬이 실제 데이터 구조를 만들어 준 것으로 설명하지 않는다.

## 결과물과 반영 경계

- `index.html`, `review.css`, `review.js`, `fonts/`: 독립 시안. 외부 API/SDK/분석 전송 없음.
- `desktop-1280x720.png`: 핵심 정보와 버튼을 한 화면에서 확인하는 시안.
- `narrow-752x720.png`: 좁은 창 대응 설명 이미지.

- `capture.html`: 크기 검수용 iframe. 실제 서비스 코드가 아니다.

사용자가 이 디자인을 승인한 뒤 실제 관리자 shell/terms-workbench/styles를 변경한다. 처음 반영할 때는 읽기·미리보기 레이아웃과 용어 전용 진입/메뉴 정리만 적용하고, 저장 권한은 기존 capability가 열릴 때까지 잠가 둔다. 현재 사용자가 진행 중인 Flutter/디자인 파일 수정은 건드리지 않는다. 커밋한다면 새 디자인 문서/진행 기록만 포함하며 배포를 수동 실행하지 않는다.
