# ROOTGIST 관리자 운영 범위 — 용어만 사람 검수

2026-10-28 · 사용자 결정: “용어만 검수하고 나머지는 자동으로 진행”

## 현재 우선하는 결정

기존 6개 화면 시안과 전체 콘텐츠 편집 계획보다 이 결정이 우선한다. 현재 앱의 노출 정책과 배치 자동 처리 동작은 유지한다.

| 대상 | 운영 방식 | 관리자 웹 역할 |
|---|---|---|
| 용어 의미·한국어 표기·영문 별칭·추출 후보 | 사람 검수 | 검토·수정·승인·반려·초안 및 변경 이력 |
| 논문별 용어 적용 | 사람 검수 | sense 연결, ko_span, sentence_ids, highlight 및 앱 표시 확인·수정 |
| 논문 수집·요약·번역·공개 | 기존 워커 자동 처리 | 원문·번역을 용어 검수 문맥으로 조회. 처리 상태·오류 확인 |
| 공식 뉴스·모델 수집·요약·갱신·공개 | 기존 워커 자동 처리 | 조회·상태·오류 확인 |
| 출처·배치 운영 | 기존 자동 작업 유지 | 관측 가능한 상태 조회. 실행 이력이 없으면 미연동 표시 |
| 공지 | 현재 앱 번들 구조 유지 | 새 원격 작성·게시 및 자동 생성은 이번 범위에 포함하지 않음 |

- 논문·뉴스·모델에 사람 승인 관문을 새로 만들지 않는다. 미검수 용어가 있다는 이유로 전체 논문/뉴스 자동 공개를 막지 않는다.
- 미승인 용어의 앱 노출은 기존 RPC와 app_config 정책을 유지한다. 새로운 차단/일괄 공개 규칙을 임의로 추가하지 않는다.
- 기존 논문/뉴스 승인 버튼은 R0 비활성 시안이며 현재 배치 흐름을 막는 기능이 아니다. 후속 UI 정리에서 이 승인 버튼을 제거하고 화면의 역할을 조회·상태 확인으로 명확히 한다. 이번 기록 갱신에서는 앱 코드를 바꾸지 않았다.

## 축소한 다음 구현

1. 용어에 필요한 초안·변경 이력·트랜잭션·revision/hash·충돌 감지·operation_id 멱등성을 구체화한다. paper/news/model 편집을 위한 범용 CMS는 만들지 않는다.
2. 워커가 사람의 용어 수정본을 덮어쓰지 않도록 보호한다. 논문 전체 AI 결과를 동결하지 않는다. 원문/문장/번역이 재생성되어 적용 위치가 달라지면 용어 연결을 재검토 대상으로 표시하는 계약을 검토한다. 바뀐 번역에 이전 ko_span을 무조건 재적용하지 않는다.
3. 보호가 통합·검증된 다음 용어 의미·별칭·후보·적용 위치 저장을 활성화한다. 현재는 모든 DB 쓰기 차단을 유지한다.

## 기존 계획에 대한 적용

- M4~M6/R1은 용어 쓰기에 필요한 범위로 축소한다.
- M7/R2 논문·뉴스·모델의 수동 편집·승인은 현재 구현 범위에서 제외한다.
- M8 공지 서버 게시와 앱 연결은 보류한다. 자동 공지 생성을 새로 요구한 것으로 해석하지 않는다.
- M9의 출처 편집·차단 URL 쓰기는 현재 범위에서 제외하고 운영 조회만 보조 기능으로 둔다.
- 이번 실제 연결 검증을 위해 별도 운영·스테이징 DB나 테스트 계정은 만들지 않았다. 기존 ROOTGIST_DB는 현재 읽기 전용 연결로 사용한다. 향후 쓰기 변경은 로컬 검증 방법과 구체적인 운영 적용 패키지를 갖춘 뒤 별도로 적용한다.

## 현재 구현과의 차이

여섯 화면의 조회와 기존 R0 비활성 버튼은 현재 코드에 남아 있다. 용어 저장·초안·승인도 아직 구현되지 않았다. 기존 워커·Flutter·DB·마이그레이션·자동 배포 흐름을 수정하지 않았다.
