## P8. 출처·신뢰 신호 확장 (HF Trending 포함)

- **배경**: 사용자 의견 「HF Daily Papers도 arXiv 기준이고, arXiv는 심사 전에 올리는 곳이라 신뢰성이 떨어진다. AAAI 같은 학회나 GitHub 별 많은 레포, Claude·GPT 공식 소식처럼 공부할 만한 곳이 더 있을까」, 「Hugging Face Trending은 매력적」.
- **짚어 둘 것**
  - arXiv는 심사 전 사전 공개 서버다. 다만 주요 학회 채택 논문도 대부분 arXiv에 같이 올라오므로 「arXiv = 미검증」이 아니라 「검증 여부를 아직 모름」에 가깝다.
  - HF Daily Papers의 순서는 커뮤니티 upvote다. 화제성 신호이지 품질 보증이 아니다(이미 데이터 출처 화면에 적혀 있다).
  - 그래서 **출처를 늘리기 전에 지금 논문에 신뢰 신호를 덧붙이는 것**이 작고 효과가 크다.

### HF Trending 확인 결과 (2026-10-26, 공개 API 직접 호출)

- `GET https://huggingface.co/api/models?sort=trendingScore` — 키 없이 바로 된다. `datasets`, `spaces`도 같은 모양. 항목마다 `trendingScore`, `likes`, `downloads`, `pipeline_tag`(과제 종류), `createdAt`, `tags`(`license:…`, `arxiv:…`)가 온다.
- 상위 10개 모델 중 **논문(`arxiv:` 태그)이 연결된 것은 3개**였다. Trending은 「논문」보다 「모델 출시」 소식에 가깝다.
- 라이선스는 apache-2.0·mit도 있지만 `other`(개별 조건)도 섞인다.
- 상위권에 성인·검열 해제(「Uncensored」) 계열 모델·Spaces가 섞여 있었다. **그대로 노출하면 안 되고 거르는 규칙이 필요하다**(이름·태그 차단 목록 + 사람 확인).
- 「Trending Papers」(huggingface.co/papers/trending)는 웹 페이지만 있고 공개 JSON API는 확인되지 않았다(`/api/papers/trending` 404). 쓰려면 페이지를 긁어야 해서 깨지기 쉽다. 지금 쓰는 `/api/daily_papers`는 그대로 된다.

| **8b** 코드·모델 링크 | HF 논문 페이지에 연결된 GitHub 레포(별 수)·HF 모델을 S02 정보 카드에 ↗ 행으로 | 배치(HF 논문 상세 API), S02 | S |

| 8d 공식 발표 피드 | 연구소 블로그 제목·날짜·링크(본문 요약 없이) | 배치(RSS), 새 화면, 권리 검토 | M~L |

- **추천 순서**: 8a → 8c → 8b. 8a는 「신뢰성」 고민에 바로 답하고, 8c는 사용자가 매력적이라고 한 부분이며 논문 피드와 겹치지 않는다.
- 8c의 LLM 요약(모델 카드 한국어 요약)은 처음에는 넣지 않는다. 모델 카드 권리·정확도 검토가 따로 필요하다.
- 불변 원칙 「매일 상위 10편 읽기 앱」의 범위가 넓어지는 결정이라 HANDOFF 1장(범위) 변경이 함께 필요하다.

- **정할 것**: 8a를 MVP(외부 공개 전)에 넣을지, 8c 위치(홈 아래 섹션 / 탐색 탭 / 새 탭), 8c 거르기 기준(과제 종류 화이트리스트로 시작할지).

## P9. 정보 구조 v2 — 홈 하이라이트, 탐색을 출처별 허브로

- **배경**: 사용자 의견 「GitHub나 공식 사이트 소식들을 탭으로 구분하고, 메인엔 여러 종류 중 가장 흥미로운 것들을 모아 주면 어떨까. 하단 탭으로 두기엔 너무 많으니 확장형 탭이나 다른 아이디어가 필요할 것 같다. Trend는 모델 설명도 필요하지 않을까」.
- **전제**: P8의 출처(모델·코드·공식 소식)가 들어온다는 가정이다. 「매일 상위 10편 논문 읽기」에서 「AI 최신 소식」으로 범위가 넓어지므로 HANDOFF 1장(범위)·불변 원칙 검토가 먼저다. **외부 공개 뒤 v2**로 본다.

### 하단 탭은 4개 그대로

확장형 탭바·「더보기」 탭은 숨긴 항목을 찾기 어려워(iOS에서 특히) 쓰지 않는다. 비교한 안:

| 안 | 모양 | 장점 | 단점 |
|---|---|---|---|
| **A(추천)** 홈 = 하이라이트, 탐색 = 출처별 허브 | 홈은 종류별 대표를 섞어서. 「탐색」 위쪽에 가로로 넘기는 탭(논문 · 모델 · 코드 · 공식 소식) | 하단 탭 유지, 출처가 늘면 가로 탭만 는다 | 지금 「탐색」(지난 날짜 목록)은 「논문」 탭 안으로 옮겨야 한다 |
| B 홈 맨 위 종류 칩 | 홈 상단 「전체 · 논문 · 모델 · 코드 · 소식」 칩 | 한 화면에서 전환 | 분야 칩(언어 모델·에이전트…)과 칩 줄이 두 개가 된다 |
| C 홈 자체를 가로 탭 | 뉴스 앱처럼 홈 상단 탭 좌우 넘김 | 익숙함 | 「오늘 가장 흥미로운 것」을 모으는 홈 역할이 흐려진다 |

### 홈 하이라이트: 종류별 1칸

- 점수의 성격이 출처마다 달라(논문 upvote, 모델 trendingScore, 레포 별 증가량, 발표 최신순) 한 줄로 섞어 순위를 매기지 않는다. **종류별 1등을 한 칸씩**: 주요 논문 1 → 뜨는 모델 1 → 뜨는 레포 1 → 공식 발표 1 → 그 아래 지금처럼 논문 목록.
- 칸마다 종류 배지와 **고른 이유**를 한 줄로(예: 「이번 주 다운로드 급상승」, 「upvote 1위」). 이유를 말할 수 없는 항목은 올리지 않는다.
- 비어 있는 종류(예: 그 주 공식 발표 없음)는 칸을 숨긴다.

### 모델 설명 (Trend)

이름만으로는 무엇인지 알 수 없다(`Qwen3.8-27B`, `flint`). HF 모델 상세 API(`/api/models/{id}`, 2026-10-26 확인)로 만든 곳(`author`), 과제(`pipeline_tag`), **파라미터 수**(`safetensors.total`, 예 27.8B), 라이브러리, 라이선스, 연결 논문(`arxiv:` 태그)을 받을 수 있다.

1. **메타데이터 한 줄 설명(먼저)**: 틀에 맞춰 조립. 예 「Qwen이 공개한 278억 파라미터 이미지·텍스트 이해 모델 · Apache-2.0」. LLM이 없어 틀릴 일이 없고 권리 문제도 없다. 과제 이름은 한국어 대응표(`image-text-to-text` → 이미지·텍스트 이해)를 둔다.
2. **연결 논문이 있으면 기존 파이프라인 재사용**: 그 논문의 한국어 요약·핵심 내용(근거 문장 연결)을 붙인다.
3. **「제작사가 내세운 강점」 카드(모델 카드 LLM 정리)**: 「어디에 뛰어난가」는 정리된 데이터가 없다. HF의 평가 결과 칸(`model-index`)은 트렌딩 모델 4개 모두 비어 있었고(2026-10-26), 강점·점수는 모델 카드 본문에 제작사가 자유 형식(표·HTML·그림)으로 적는다. 설명이 거의 없는 카드도 있다(LTX-2.5, 126자).
   - 카드에서 강점 2~3줄, 대표 벤치마크 점수, **제작사가 밝힌 한계**를 뽑는다. 근거는 카드에 적힌 내용만(지금 논문 요약과 같은 규칙), 뽑은 문장마다 카드 원문 위치를 남겨 검증한다.
   - 벤치마크 이름은 한국어로 풀어 쓴다(대응표): SWE-bench → 실제 GitHub 이슈를 고치는 코딩 능력, Terminal-Bench → 터미널에서 명령으로 일을 끝내는 능력, GPQA → 대학원 수준 과학 문제 풀이 등. 대응표에 없는 이름은 풀이 없이 이름만.
   - 점수는 「제작사 측정」 머리말을 달고, 카드 아래에 「모델 카드에 적힌 제작사 발표를 AI가 정리했어요. 독립적으로 검증된 결과가 아니고, 평가 방식은 출처마다 달라요」. 서로 다른 벤치마크 점수를 막대로 나란히 그리지 않는다(같은 척도로 보이게 하지 않기).
   - 카드에 강점이 없으면 「제작사가 모델 카드에 강점이나 평가 결과를 밝히지 않았어요」라고 적는다. 지어내지 않는다.
   - 연결 논문이 있으면 논문 요약을 먼저 보여 준다(근거 연결이 검증돼 있다).
   - 권리: 카드 글의 권리는 모델 라이선스와 별개라 A8에 추가한다. 독립 평가(LMArena 등)는 대화형 LLM 위주이고 재사용 조건 확인이 필요해 나중 단계로 둔다.

### 순서

1. P8a 학회 채택 배지(지금 구조 안)
2. 탐색 → 출처별 허브, 「모델」 가로 탭 추가(메타데이터 설명) = P8c
3. 홈 하이라이트 종류별 칸
4. 「코드」·「공식 소식」 가로 탭(P8b·P8d)

- **시안**: 홈 하이라이트, 탐색 허브(모델 탭), 모델 상세 2종(강점이 카드에 있는 flint / 밝히지 않은 LTX-2.5). 앱 토큰으로 그린 정적 시안(2026-10-26, 레포 밖 비공개 페이지). 모델 값은 HF 공개 API·모델 카드 실제 값.
- **정할 것**: A안으로 갈지, 가로 탭의 이름·순서, 홈 하이라이트 칸 수, 모델 설명 1단계로 시작할지.
