# ROOTGIST 디자인 시스템

작성 2026-10-27 · 기준 코드 `feature/official-news` 브랜치

이 문서만 보고 같은 화면을 다시 만들 수 있도록, 지금 앱에 들어간 값(색·글자·간격·부품·동작)을 그대로 적는다. 화면별 구성과 기능은 [SCREENS.md](SCREENS.md)에 있다.

- 값의 원본은 코드다: `lib/design/tokens.dart`(색·간격·모서리·그림자), `lib/design/typography.dart`(글자), `lib/design/widgets/`(공통 부품). 이 문서와 코드가 다르면 코드가 맞고, 이 문서를 고친다.
- `docs/HANDOFF.md` 5~7장과 `docs/design/ui_v2.1/`은 처음 시안(v2.1)이다. 그 뒤 실기기 QA로 바뀐 점(홈 하이라이트, 탐색 3칸, 공식 소식·모델, 공유·북마크, 새 글 점 등)은 이 문서가 최신이다.
- 단위는 모두 **pt(논리 픽셀)**. 기준 기기는 iPhone 17(폭 402pt). 화면 이미지는 `docs/design/screens/`(가상 데이터, 가로 603px = 1.5배).

## 1. 원칙

1. **읽는 앱이다.** 흰 카드 위의 글이 주인공이다. 장식·일러스트·그라데이션을 쓰지 않는다.
2. **흑백에 점 하나.** 화면은 따뜻한 회색 계열 흑백이다. 색은 「새 글」 점(`newDot`) 하나만 쓴다.
3. **근거와 원문으로 닿는다.** AI가 만든 글에는 원문 근거 링크와 「AI가 정리했어요」 안내를 붙인다. 원문 전체를 옮기지 않는다.
4. **한국어 줄바꿈은 어절 단위.** 모든 한국어 문장은 단어 중간에서 줄이 바뀌지 않게 그린다(7장 keep-all).
5. **말투는 해요체.** 버튼·안내·AI 요약 모두 「~해요」. 합니다체·「~다」는 쓰지 않는다(논문 초록 번역문만 예외: 원문 문체를 따르는 평서체).
6. **누르는 곳은 44pt 이상.** 보이는 모양이 작아도 누르는 영역은 44×44pt를 지킨다.

### 2.1 대표 카드 (2026-10-31)

그날 주요 논문·트렌딩 1위 같은 대표 카드(`RgFeaturedCard`)도 일반 카드와 같은 면(`surfaceCard`)이다. 모서리(26)·여백(22)·큰 제목으로만 띄운다. 예전 차콜 면은 밝은 카드 사이에서 튀어 없앴다(사용자 피드백).

### 2.2 어두운 화면 (2026-10-31)

설정 › 읽기 설정 › 화면 모드: 기기 설정(기본) / 밝게 / 어둡게. 값은 `lib/design/tokens.dart`의 `RgPalette.dark`(바탕·카드·칩·선)와 `RgInk.dark`(글자·주 버튼·시트·하이라이트)가 정본이다. 어두운 화면에서는 화면 바탕(흰색·종이) 선택을 쓰지 않는다.

- 면의 층: 바탕 `#0C0C0B` → 카드·탭바·시트 `#222220`(바탕 대비 1.23:1, 카드가 떠 보이게) → 칩 `#30302D` → 선택 알약 `#4E4E49`.
- 글자: 주 `#EDEDE9`, 본문 `#CFCFC9`, 보조 `#A3A39C`(카드 대비 6.3:1), 장식 `#75756F`.
- 주 버튼은 뒤집힌다: 밝은 면 `#EDEDE9` + 검정 글자. 리더 조절 알약도 어두운 트랙 + 밝은 선택 칸.
- 용어 하이라이트: 어두운 노랑 `#4A3F12`(열림 `#66561A`) + 밝은 글자.
- 출처 배지 위 글자(`onBrand` 흰색, `onBrandLight` 검정)는 두 모드에 같다. OpenAI·xAI 검정 배지는 어두운 화면에서 `#3A3A36`.

### 3.3 글자 크기 키우기(접근성)

시스템 글자 크기를 따라 커진다. 단, 영역마다 상한이 있다.

| 영역 | 상한 | 이유 |
|---|---|---|
| 화면 틀: 상단 바(52), 하단 탭바(64), 탐색 칸 이름 | **1.35배**(`ChromeTextScale`) | 높이가 고정된 틀이 넘치지 않게. iOS 기본 바와 같다 |
| 21pt 이상 큰 제목(`displayHome`·`titleDetail`·`titleReader`·`titleFeatured`·`serifTerm`) | **2배**(`HeadingTextScale`) | 접근성 최대(3.12배)에서 홈 헤드라인이 화면을 다 차지했다 |
| 칩·세그먼트 글자 | **2배**(`rgPillTextScaler`) | 4등분 세그먼트 칸에 들어가게 |
| 그 밖의 본문 | 상한 없음 | |

앱 안의 **글자 크기 4단계**(작게 0.9 · 기본 1.0 · 크게 1.15 · 아주 크게 1.3)는 시스템 배율에 곱해서 **S02 AI 카드와 S03 리더 본문에만** 적용한다.

## 5. 공통 부품

### 5.1 카드 `RgCard`

흰 바탕, 모서리 24, 그림자 `card`, 화면 좌우 16 안쪽. 안쪽 여백은 쓰는 곳이 정한다(목록 카드 0, 내용 카드 20/18). 내용이 모서리 밖으로 나가지 않게 잘라 낸다.

### 5.2 목록 행 `RgListRow`

- 최소 높이 56, 안쪽 여백 위 18 · 오른쪽 8 · 아래 18 · 왼쪽 20.
- 왼쪽 글 열(남는 폭 전부) + 간격 8 + 오른쪽 부품(북마크 또는 셰브론).
- 마지막 행을 뺀 모든 행 아래에 1pt `dividerCard` 줄(카드 폭 전체).
- 오른쪽 부품은 위쪽 정렬(제목 첫 줄과 맞춤). 지난 날짜 행만 가운데 정렬, 여백 16/16/16/20.
- 행 전체를 누르면 이동하고, 오른쪽 버튼은 따로 눌린다(행 이동 없이).

### 5.3 배지 `RgBadge`

최소 높이 24, 좌우 10 · 위아래 4, 알약, `caption` 500 `textBody`. 바탕은 카드 위면 `fillBadgeOnCard`, 바탕 위면 `fillBadgeOnBg`. 주제(언어 모델), 출처(OpenAI), 「모델」, 「지연」.

### 5.4 원형 버튼 `RgCircleButton`

44×44 원, 아이콘 20(또는 글자 「가」 15/600).

| 변형 | 모양 | 쓰는 곳 |
|---|---|---|
| `outline` | 흰 바탕 + `borderDefault` 1pt | 상세 화면 상단 바 오른쪽(↗·가·공유·북마크) |
| `neutral` | `fillNeutral` 바탕 | 리더 상단 바 「가」, 목록·카드의 북마크(보이는 원 36, `visualSize`) |
| `filled` | `actionPrimary` 바탕, 흰 아이콘 | 저장된 북마크(상단 바·목록 모두) |
| `plain` | 바탕 없음 | 뒤로 가기(`RgBackButton`) |

뒤로 가기 `RgBackButton`: 원 없이 화살표만(`plain`, `textPrimary`). 누르는 영역 44는 그대로이고, 화살표가 아래 제목(좌우 20)과 같은 세로줄에 오도록 16pt 왼쪽으로 당긴다. 모든 하위 화면과 리더에 같다.

보이는 원 크기 `visualSize`: 누르는 영역(44)은 그대로 두고 그 안 가운데에 더 작은 원(목록·카드 36)을 그린다.

북마크 버튼 `RgBookmarkButton`: 저장 전 `bookmark`(빈 아이콘), 저장 후 `bookmark-filled`. neutral·outline이면 저장 후 검정 원(`filled`)으로 바뀐다. 화면 읽기: 「북마크에 저장」 / 「저장됨, 북마크 해제」.

### 5.5 공유·북마크 묶음 `ItemActions`

카드·목록 행 오른쪽의 북마크(+ 공유).

- **목록·카드(기본):** 북마크만, `neutral` 옅은 원(보이는 36, 누르는 44). 피드백 2차: 행마다 회색 아이콘 두 개가 반복돼 시선이 흩어지고 버튼인지 잘 안 보였다.
- **공유가 붙는 곳(`share: true`):** 상세 화면 상단 바(`outline`, 간격 8)와 상세 화면이 없는 업데이트 카드(`neutral`, 간격 0).
- 논문 목록 행·추천 카드·발표 행·모델 행·보관함 행은 북마크만 둔다. 공유는 상세 화면에서 한다.

- 공유: 기기 공유 화면에 「제목 줄바꿈 원문 주소」를 넘긴다. 논문은 `https://huggingface.co/papers/<id>`, 소식·모델은 원문 주소.
- 북마크: 보관함에 종류(논문·공식 소식·모델)와 출처를 함께 저장한다.
- 추천 카드·업데이트 카드에서는 오른쪽 위 모서리 쪽으로 (12, −10) 옮겨 붙인다(누르는 영역은 그대로).
- 보관함 행의 북마크도 같은 모양(저장됨 = 검정 원)이고, 누르면 보관함에서 뺀다.

## 7. 글과 표기 규칙

- **keep-all(어절 단위 줄바꿈):** Flutter에는 CSS `word-break: keep-all`이 없어, 어절 안 글자 사이에 보이지 않는 문자(U+2060 word joiner)를 넣어 그린다(`keepAll()`, `KeepAllText`). 화면 읽기에는 원래 문장을 넘긴다. 한국어가 들어갈 수 있는 모든 글(제목·요약·메타·값)에 쓴다.
- **용어:** 논문(arXiv 논문, 단위 「편」), 공식 발표(연구소 블로그 글), 업데이트(릴리스·개발자 공지), 공식 소식(발표 + 업데이트를 묶는 탐색 칸 이름), 모델(HF 트렌딩), 항목(보관함, 단위 「개」). 「연구」는 공식 소식의 분류 이름(Research)에만 쓴다.
- **날짜:** 모두 한국 시간. 헤드라인·날짜 행 「10월 18일 일요일」, 메타 「10월 18일」, 논문 발행일·모델 공개일 「2026.10.18」, 공지 「2026.10.27」, 시각 「05:12」.
- **숫자:** 1만 미만은 쉼표(1,234), 1만 이상은 「5.7만」(10만 이상은 소수 없이 「12만」). 파라미터 「400억 파라미터」, 1조 이상 「1.2조 파라미터」.
- **AI 표시:** AI가 만든 글이 있는 화면에는 ⓘ 안내 문구를 둔다(문구는 SCREENS.md 각 화면).
- **문장마다 줄바꿈:** 여러 문장인 안내 문구(ⓘ), 공식 소식 요약, 공지 본문, 데이터 출처 문단, 빈 날 안내는 문장마다 줄을 바꾼다(`KeepAllText(perSentence: true)`, `byLine()`). 한글·닫는 괄호 뒤 마침표에서만 나눈다(「3.0배」는 그대로). 논문 AI 요약은 문장마다 문단(간격 8).

## 8. 동작 규칙

### 8.1 누름과 이동

- 누름 표시: 물결 대신 불투명도 0.85(100ms). 모든 누를 수 있는 것에 같은 방식.
- 화면 이동: 오른쪽에서 밀려 들어오는 iOS 기본 전환. 하위 화면은 바탕(`bgApp`)이 불투명하다(전환 중 뒤 화면이 비치지 않게). 왼쪽 가장자리에서 밀면 뒤로 간다.
- 탭 위로 띄우는 화면(탭바 없음): 논문 상세, 리더, 공식 소식 상세, 모델 상세. 어디서 열어도 뒤로 가면 연 화면으로 돌아간다.
- 탭 안에서 여는 화면(탭바 보임): 지난 날짜, 공지사항, 데이터 출처, 개인정보 처리방침.
- 상태바 밑에는 `bgApp` 띠를 깔아, 스크롤한 글이 시계·배터리와 겹치지 않게 한다.

### 8.2 탐색 칸 넘기기

제목과 칸 줄은 고정, 아래 내용만 좌우로 넘어간다(PageView). 칸 이름을 누르면 250ms easeOut으로 넘어간다. 홈의 「더 보기」는 탐색의 해당 칸으로 바로 간다(「업데이트 더 보기」는 공식 소식 칸의 「업데이트」를 고른 상태로).

### 8.3 새 글 점

- 「새 글」 = 이 기기에서 아직 안 연 글 + 7일이 안 된 글 + 기준 시각 뒤에 올라온 글.
- 기준 시각은 앱을 처음 실행한 때의 3일 전이다. 설치하자마자 모든 글이 새 글이 되지 않게 하면서, 최근 며칠 것은 알려 준다.
- 공지사항: 그 공지를 열면 사라진다. 공식 소식: 상세를 열면(업데이트 카드는 원문을 열면) 사라진다.
- 표시 위치: 공지사항 행(점 + 「새 글」), 설정 › 공지사항 행, 탭바 「설정」, 공식 소식 행의 출처 줄 앞, 탐색 「공식 소식」 칸.
- 논문(매일 새로 올라옴)과 모델(순위표)에는 달지 않는다.

### 8.4 저장

북마크, 읽기 설정(초록 기본 보기·글자 크기), 읽음 기록, 받은 데이터 저장본은 기기에만 저장한다(`shared_preferences`). 서버로 보내지 않는다.
