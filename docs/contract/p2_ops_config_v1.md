## 1.1 배치 일정과 선별 (P1 결재 안건, 2026-10-17 결정)

| 항목 | 값 |
|---|---|
| 배치 시각 | 매일 **KST 05:00**. 전날(UTC D) 목록을 처리해 출근 시간 전에 보여 준다 |
| 대상 | HF Daily Papers `date=D` 전체를 받은 뒤 **상위 10편만** 해설 생성 |
| 선별 | upvote 내림차순 → `paper.publishedAt` 최신순 → `paper_id` 오름차순. upvote는 배치 시각 값으로 고정해 저장 |
| 0편인 날 | 빈 날로 표시 |
| 다음 날 보충 | 다음 배치에서 D 목록을 다시 받아 늦게 추가된 논문을 보관 목록에만 더한다. 노출한 상위 10편은 바꾸지 않는다. 늦게 추가된 편수를 매일 기록한다 |
| 원문 링크 | `huggingface.co/papers/{id}` 기본, `arxiv.org/abs/{id}` 보조 |
| 기관 | "게시 조직"으로 표기, 없으면 미표시 |
| 소요 시간 | 상위 10편 기준 deepseek 약 10~15분, 예비 모델 전환 시 최대 약 1시간 |

## 2. 실패 처리

| 상황 | 판단 기준 | 처리 |
|---|---|---|
| 출력 한도 초과 | `finish_reason=length` 또는 본문 없음 | 같은 모델로 **1회 재시도**. 진단상 폭주는 확률적으로 일어나 재시도로 대부분 해결됨 |
| 빈 응답·JSON 파싱 실패 | 본문이 JSON이 아님(코드 펜스 안 JSON은 꺼내서 다시 시도) | 1회 재시도 |
| HTTP 429·5xx, 시간 초과, 연결 끊김 | 응답 코드 또는 예외 | 간격을 늘려 최대 2회 재시도(10초, 20초) |
| 재시도 후에도 실패 | — | **예비 모델로 전환**해 1회 시도. 그래도 실패하면 그 논문은 "해설 준비 중"으로 두고 다음 배치에서 다시 시도 |
| 스키마 검증 실패 | `p2_validate`의 검사 1~4(스키마, 문장 ID 집합·순서, 근거 ID, 고정 용어 보존) | 1회 재시도 후 예비 모델 |

- 모든 호출은 프롬프트 해시, 모델, 설정, 토큰, 지연, 결과, 오류를 기록한다(현재 `calls.jsonl` 항목과 같음).
- **Python 3.9 주의:** 응답을 읽다 나는 시간 초과(`socket.timeout`)는 `TimeoutError`가 아니라 `OSError` 하위다. 잡지 않으면 작업자 스레드가 조용히 죽는다(본 평가에서 2건 발생).

## 3. 앱 후처리

모델이 규칙을 놓친 경우를 대비해 저장 전에 처리한다. 원본 응답은 따로 보관한다.

| 항목 | 처리 |
|---|---|
| 요약 길이 | v0.5.2에서 글자 수 규칙을 뺐기 때문에 길이가 들쭉날쭉하다(확인 실행 396~669자). 화면 표시 상한을 정하고 넘으면 줄여 보여 준다. 저장된 요약은 고치지 않는다 |
| LaTeX 잔여 표기 | `\%`·`\_`·`\&`·`\#`·`\$` → 표시 문자, 숫자 옆 `times` → `×`, `~` 공백 명령 → 공백. 원문 초록 표시에도 같은 규칙(P1 결재 안건 A6) |
| 외국 문자 | 한자·가나가 나오면 경고로 기록하고 재시도 대상으로 둔다(확인 실행에서는 0건) |
| 분류 코드 | 허용 코드 밖이면 버리고 `other`로 둔다 |

## 5. 알려진 한계

- v0.5.2 확인은 3편 × 2모드 × 2모델 + 재현 시험 2회(14회)로 표본이 작다.
- deepseek에서도 드물게 폭주가 관찰됐다. v0.5 계열 호출 26회 중 2회로, 모두 P17 자동 선정(v0.5, v0.5.1)이었다. v0.5.2 6회와 진단 반복 8회에서는 0회였다. 재시도 규칙으로 대응한다.
- 무료 등급의 정확한 출력 상한은 확인하지 않았다. glm이 29,082토큰까지 정상 출력한 사례가 있다(v0.5.1 P05 자동 선정). v0.5.2에서 glm의 최대 출력은 26,346토큰이었다.
